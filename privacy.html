Alert Reader

Privacy policy

Last updated: 13 September 2026.

This policy describes the Gmail connection for Alert Reader, a tool that collects public links from selected email alerts. Mail access begins only after the account owner authorises the connection.

What the reader accesses

The reader requests Google's Gmail read-only permission. This permission technically covers the mailbox; Google does not offer a permission limited to one label.

During connection setup, the account email address is checked against the configured owner. Other accounts are rejected before a connection is saved. This identity check does not read messages. The expected account address is stored with the encrypted connection so it can be checked when processing is enabled.

The reader uses label metadata to find the exact label Alert Reader/SEEK. Every message-list request is restricted to that label. Before retrieving a body, it checks that the message still has that label and that its sender is from SEEK. It rechecks those conditions before exporting a result. If the label is missing, renamed or cannot be checked, the reader stops rather than searching elsewhere.

Each run is limited to recent alerts from the preceding 30 days, with time and message limits. It does not fetch attachments or parse attached forwarded messages. Read-only permission does not allow it to send, edit or delete mail.

How the information is used

Message content is processed transiently to extract public SEEK vacancy links. Personalised tracking parameters are removed. The links are organised in a private workspace; relevance and availability still require checking.

Email bodies, subjects, sender addresses and Gmail message IDs are not written to the repository, link feed, app or application logs. The reader does not send raw emails to an AI service. It does not sell email data or use it for advertising or training general-purpose AI models.

Where processing and storage happen

Google supplies the authorised Gmail data. Scheduled intake runs in a private GitHub Actions workflow. Connection credentials are stored as encrypted GitHub repository secrets and are used only for this connection. Google and GitHub handle data on their services under their own policies.

Only canonical public vacancy links and intake health information, such as check times, counts and fixed error messages, leave the intake stage. Links and associated public listing details can be retained in the private feed and workspace, including archived records. Disabling Gmail access does not automatically remove previously collected links.

Your control

The owner controls which messages receive the label. Removing the label from a message excludes it from subsequent scans. Revoking this app's access in Google Account connections stops future authorised Gmail reads. The owner can also disable the scheduled intake and remove its connection secret in the private GitHub repository.

Access will not be expanded to other email senders or labels without a new instruction from the owner.

Google data-use requirements

The reader's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

This information website

These static pages contain no sign-in form, analytics scripts or application cookies. They do not display emails, workspace preferences, credentials or private feed data. GitHub Pages records visitor IP addresses for security purposes as described in the GitHub privacy statement.

Questions and changes

For questions about the reader, contact the repository owner through the information repository. Do not post email content or credentials in a public issue. Changes to the reader's handling of Gmail data will be disclosed here before the changed behaviour is enabled.
